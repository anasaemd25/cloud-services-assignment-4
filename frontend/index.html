Application Description

This is a 3-tier web application running on CSC Rahti:

  • Frontend: An Nginx web server open to the public through a Rahti Route.
  • Backend: A Python Flask REST API running inside the private cluster network.
  • Database: A MySQL database connected to a Persistent Volume Claim (PVC) to store data safely.

Configuration: ConfigMaps vs. Secrets

I used a ConfigMap for normal settings that don't need to be hidden, like DB_HOST or DB_NAME. For sensitive stuff like database passwords, I used a Secret instead. Secrets keep credentials safe in Rahti so passwords never get leaked or exposed on GitHub.

Database Persistence

When using Docker Compose locally, data gets saved straight to the computer's local hard drive. On Rahti, storage uses a PersistentVolumeClaim (PVC) instead. If a physical server in the cloud fails, Rahti automatically moves the database pod to another node and plugs the exact same storage back into it, so no data is lost.

Platform Comparison: Rahti (PaaS) vs. cPouta (IaaS)

IaaS forces the user to manually set up virtual machines, install the operating system, and configure everything yourself. With PaaS like Rahti, the platform manages the actual servers for you. It handles public routing, automatic scaling, and fixes broken pods automatically.

Problems Encountered

Problem: I accidentally left plain text passwords inside configuration files early on.

Solution: I removed all hardcoded passwords, stored them inside a Rahti Secret object, then referenced them through environment variables, and added a `.gitignore` file to stop private files from getting pushed to GitHub.
