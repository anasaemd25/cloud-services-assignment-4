Application Description

This is a 3-tier web app deployed on CSC Rahti:

  • Frontend: Nginx web server exposed to the public internet via a Rahti Route.
  • Backend: Python Flask REST API running inside the internal network.
  • Database: MySQL 8.0 database with a Persistent Volume Claim (PVC) for data storage.

Configuration: ConfigMaps vs. Secrets

We use a ConfigMap for non-sensitive settings (like DB_HOST). We use a Secret for sensitive credentials (like passwords). Secrets store credentials securely without exposing them in GitHub.

Database Persistence

In Docker Compose, data saves to the local hard drive. In Rahti, persistent storage uses a PersistentVolumeClaim (PVC) . If a physical server breaks, Rahti moves the database pod to a new server and reattaches the same PVC without losing data.

Platform Comparison: Rahti (PaaS) vs. cPouta (IaaS)

IaaS requires manually creating virtual machines and installing the operating system. PaaS (Rahti) manages the servers automatically. Rahti also provides built-in routing, automatic self-healing, and easy scaling.

Problems Encountered

Problem: Hardcoded passwords were in configuration files.

Solution: Moved credentials into Rahti Secret objects, referenced them via environment variables, and created a `.gitignore` file to keep local files off GitHub.
